## Native behavior and C++ choices

`editModel` observes typing and writes the query before the optional input
callback. It does not drive the display or receive selection values. Existing
index/text bindings retain immediate native typing updates. `autoexpand` defaults
to true; false preserves free input and access to the manual choice list.
Selected values use the current declared child index/value, so filtering code
should use raw values as stable identifiers.

Qt and wx retain the editor and preserve its cursor/selection when reconciling
unchanged text. Qt's completer shares the ComboBox model, preserving row identity
for duplicate labels and avoiding a copied string-list model. The popup is
independent of QLineEdit's built-in completion, so highlighting does not insert
text or write a model; native automatic item insertion is disabled. wx popup
handlers and queued geometry work belong to the native control's retained
context, with weak native references and explicit cleanup.
LVGL removes the old prefix filter, routes candidate keys before textarea text
insertion, and closes/repositions an open list after native layout changes.
Bindings and callbacks are copied before application writes that can redraw or
remove the declaration.

The cookbook keeps query and selected value in separate State fields, disables
automatic expansion for the ordinary editable example, and resets both fields
with Clear. Its sources remain shared across all four desktop targets.

The upstream avoidance of redundant native setters is useful in C++ for
preserving the caret and avoiding native widget work, independently of Python
binding overhead. Candidate lists are refreshed when declarations change; no
Python-specific object or dispatch cache is introduced. There are no painter
changes or measured performance claims in this sync, and no benchmark results
are retained.
